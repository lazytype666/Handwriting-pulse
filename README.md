# 笔迹脉搏

一张会记录书写过程的草稿纸。手指或手写笔落在画布上时开始一笔，抬起时结束。可以从导出的文件还原每一笔经过的位置、顺序和时间，检查短暂停顿是否在数据中可见。此版本的笔迹和导出文件都留在设备上。

## 在安卓设备上运行

电脑准备 Node.js 24 LTS 和 npm，手机安装与 Expo SDK 58 匹配的 [Android Expo Go](https://expo.dev/go?sdkVersion=58&platform=android&device=true)。手机和电脑连同一局域网，在电脑上打开终端。

```sh
git clone https://github.com/lazytype666/Handwriting-pulse.git
cd Handwriting-pulse
npm ci
npx expo start --go
```

保持终端打开，用手机 Expo Go 扫终端二维码，首次加载等到出现白色画布和「导出」按钮。若手机提示 SDK 不兼容，请核对 Expo Go 的 SDK 版本。连接超时时，检查两台设备是否在同一可互访的 Wi-Fi，以及电脑是否允许 Node 通过专用网络防火墙。在不允许设备互访的场地，可使用已授权 USB 调试的手机，运行 `adb reverse tcp:8081 tcp:8081`，并在 Expo Go 中打开 `exp://127.0.0.1:8081`（适用于开发服务器使用 8081 端口时）。

## 书写与导出

1. 在空白处书写。左上角显示最近一秒内收到的点数，以及最近两个点的时间戳差。轻触「隐藏」可收起面板，再点「显示诊断」即可展开。停笔约一秒后，点数归零，点间隔保留上次的值。
2. 点右下角「导出」。屏幕中央显示总笔数、总点数和可长按选择的完整文件 URI。每次导出创建一个新文件，画布保留当前笔迹，后续可继续写。
3. 安卓文件管理器对应用私有目录有访问限制。要把数据拿到电脑，点「另存到手机文件夹」，在系统文件选择器中选择「文档」内的一个子文件夹并允许使用。随后可从手机的「文件」应用或通过 USB 文件传输取出 JSON。取消选择时原件仍在应用文档目录。

画布数据驻留在当前会话内。重载、退出项目或系统回收进程前，请先导出要保留的笔迹。

## 现场验收

从空白页开始，连续画圈约 12 秒，保持移动并只在结束时抬笔。再写一个点和一条短线，各抬笔一次。此时导出应有三笔。收起、展开诊断面板，检查线条仍在原位。再写一笔并重新导出，第一份文件应仍保留三笔，第二份应有四笔。

把第一份文件另存并复制到电脑，运行以下命令（替换文件名）。

```sh
node tools/verify-recording.mjs "本次导出的文件.json"
```

脚本检查 JSON 字段、计数、有限坐标、笔 ID 唯一性，以及跨笔时间戳严格递增。对于每一笔时长至少 10 秒的数据，脚本检查满一秒后的**全部**滚动窗口，给出最低值、最高值和首次最低值出现的时间。全部受检窗口均达到 60 点/秒时退出码为 0，格式或速率不达标为 1，缺少足够长的单笔样本为 2。要测持续移动时的速率，应将静止停笔留到另一笔单独演示。

采样率受触控硬件、系统的事件合并和手势事件分发影响。测量现场请保留设备型号、输入方式和导出原件，以该次文件作为成绩依据。

在 OPD2506 平板（Android 16、Expo Go 58.0.5）上，默认智能切换模式的两条真人手写长笔分别录得 57–62 和 53–61 点/秒。系统实际启用 120 Hz 时，12.790 秒的 ADB 连续划动录得 115–122 点/秒，随后的一次轻点和一条短线使导出笔数恰好为 3。自动输入覆盖系统事件到 JSON 的链路；评估手写笔硬件时请以该笔的实际书写样本为准。

这台设备的应用刷新率受「设置 → 显示与亮度 → 屏幕刷新率」控制。「高刷新率」下可在「自定义应用刷新率」查看 Expo Go 的选项。其他设备可直接从诊断区观察书写中的点数，再导出文件复核。

## 数据与实现

| 字段 | 含义 |
| --- | --- |
| `meta.exportedAt` | 导出时刻，UTC ISO 8601 字符串 |
| `meta.strokeCount`、`meta.pointCount` | 快照中的笔数、实际采样点总数 |
| `strokes[].id` | 从 1 开始的本次会话笔序 |
| `points[].x`、`y` | 触点在窗口中的坐标，单位为 React Native 逻辑像素，保留小数 |
| `points[].t` | 对齐到 Unix 时间的整数毫秒，全会话严格递增 |

- **采集与计时**　自研逻辑在 `src/capture/`。开源 Gesture Handler 分发落笔、移动、抬笔和取消事件，Reanimated 与 Worklets 在 UI 线程执行采样。单笔锁定一个触点编号，第二根手指不会牵动笔迹。系统中断时保留已收到的点。
- **时钟与精度**　当前触摸接口没有给每个点提供可靠的硬件采样时间。应用在 UI 回调入口读取单调高精度时钟，在首次落笔时对齐 Unix 毫秒。同一整数毫秒内到达的多个点依序向后排到可用毫秒，保留全部点。该时间表示事件送达时刻，系统合并或延迟分发会影响时间精度。
- **绘制与诊断**　开源 Skia 绘制轨迹。绘制按屏幕刷新，采集按实际触摸事件。诊断点数来自实际送达时刻的滑窗，间隔对应导出中相邻两个 `t` 的差值。显示刷新与采集独立进行；没有产生触摸事件时不会补点。
- **快照与文件**　UI 线程在一次回调边界复制笔迹，正在写的一笔只包含截至该时刻的点。`src/export/` 用开源 expo-file-system 写入同目录临时文件，完成后改名，并通过 Android 系统文件选择器另存副本。

Expo、React 与 React Native 提供应用运行环境，TypeScript 使用严格模式。依赖与原生模块版本已锁定。可用 `npm run typecheck` 做类型检查，用 `npx expo export --platform android` 验证 Android 发布资源与脚本打包。

## 复核仓库样本

以下两个 JSON 来自同一台平板。每次输入依次为一次约 12.8 秒的自动划动、一次轻点和一条短线。两份文件都应识别出三笔，字段、点数和全局时间顺序均通过检查。

```sh
node tools/verify-recording.mjs samples/120hz.json
node tools/verify-recording.mjs samples/60hz.json
```

120 Hz 样本最低达到 115 点/秒，脚本退出码为 0。60 Hz 样本最低为 59 点/秒，脚本退出码为 1，可用于复现严格阈值未满足的情形。
